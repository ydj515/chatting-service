# 커밋 메시지 가이드

커밋 메시지를 작성하거나 수정할 때 읽습니다. 커밋에 포함할 실제 변경을 기준으로 작성하고,
관련 없는 작업 디렉터리의 변경은 메시지에 포함하지 않습니다.

## 작성 규칙

- 커밋 제목과 상세 메시지는 모두 한국어로 작성합니다.
- 가능한 한 Conventional Commits 형식을 따릅니다. `feat`, `fix`, `docs`, `refactor` 등
  타입과 선택적 scope, 코드 식별자·파일명은 원문을 유지하고 설명은 한국어로 작성합니다.
- Git 이력에서 기존 타입·scope 관례를 확인합니다. 과거 메시지의 언어와 관계없이
  현재 가이드의 한국어 작성 규칙을 따릅니다.
- 짧은 커밋 제목과 상세 메시지를 모두 포함합니다.
- 제목은 주요 변경을 명확하고 간결하게 요약합니다.
- 상세 메시지는 무엇을 변경했는지와 왜 변경했는지를 설명합니다.
- `추가되었습니다`, `수정하였습니다`, `변경되었음` 같은 수동형·완료형 문장 대신
  `추가`, `수정`, `변경`, `제거`, `개선`, `리팩터링`, `분리`처럼 간결한 행동 중심 표현을 사용합니다.
- 실제 변경에 집중합니다. 형식을 채우기 위해 근거 없는 배경, 효과, 추가 변경을 만들지 않습니다.
- 메시지 작성 요청만으로 커밋 생성이나 push를 실행하지 않습니다.

## 출력 형식

상세 항목 수는 실제 변경에 맞춥니다. 아래 세 항목은 형식 예시이며, 개수를 채우기 위해
변경 사항을 만들어내지 않습니다.

```text
커밋 제목:
<타입>: <한국어 요약>

커밋 상세:

- <상세 변경 1>
- <상세 변경 2>
- <상세 변경 3>
```

## 예시

지양: `로그인 검증 로직이 추가되었습니다.`

```text
커밋 제목:
feat: 로그인 요청 검증 로직 추가

커밋 상세:

- 로그인 요청에 대한 입력 검증 추가
- 유효하지 않은 인증 정보가 인증 서비스에 전달되지 않도록 차단
- 잘못된 로그인 요청의 오류 처리 개선
```
