# PR 제목·본문 가이드

PR 제목과 본문을 작성하거나 수정할 때 읽습니다. 의도한 기준 브랜치와 비교한 실제 변경을
확인하고, 직접 확인한 검증 결과를 사용합니다.

## 작성 규칙

- PR 제목과 본문은 모두 한국어로 작성합니다. 코드 식별자·파일명·명령은 원문을 유지합니다.
- 저장소의 PR 템플릿과 제출 요건을 따릅니다. 관련 이슈가 있으면 연결하고, UI 변경 등
  검토에 도움이 되는 경우 스크린샷을 포함합니다.
- 제목은 주요 변경을 명확하고 간결하게 요약합니다.
- 본문에는 변경 목적을 요약하고 구체적인 변경 내용을 설명합니다.
- `추가되었습니다`, `수정하였습니다`, `변경되었음` 같은 수동형·완료형 표현 대신
  `추가`, `수정`, `변경`, `제거`, `개선`, `리팩터링`, `분리`처럼 행동 중심 표현을 사용합니다.
- 무엇을 변경했는지, 왜 변경했는지, 어떻게 검증했는지에 집중합니다.
- 제공된 diff에 없는 변경을 언급하거나 효과를 과장하지 않습니다.
- 테스트는 실제 실행한 내용과 결과만 기록합니다. 실행하지 않았다면 `미실행`과 확인된
  이유를 적으며, 통과한 것처럼 표현하지 않습니다.
- 리뷰어가 확인할 구체적인 지점을 설명합니다. 배포 참고 사항, 후속 작업, 한계와 추가
  맥락은 변경에 근거가 있을 때만 포함합니다.
- 참고 사항이 없으면 `없음`으로 표시합니다. 형식을 채우기 위해 테스트, 위험, 배경을
  만들어내지 않으며 항목 수는 실제 변경에 맞춥니다.
- 제목·본문 작성 요청만으로 PR 생성, 게시 또는 병합을 실행하지 않습니다.

## 출력 형식

```markdown
PR 제목:
<간결한 한국어 제목>

PR 본문:

## 요약

PR의 주요 목적을 간략히 설명합니다.

## 변경 사항

- <변경 사항 1>
- <변경 사항 2>
- <변경 사항 3>

## 배경

이 변경이 필요한 이유를 설명합니다.

## 테스트 결과

- <테스트 결과 1>
- <테스트 결과 2>

## 리뷰 포인트

- <리뷰어가 중점적으로 확인할 사항>

## 참고 사항

- <배포 참고 사항, 후속 작업, 한계 또는 추가 맥락>
```

## 제목·표현 예시

지양: `로그인 검증 로직이 추가되었습니다.`

권장 제목: `로그인 요청 검증과 오류 처리 개선`

권장 변경 항목: `유효하지 않은 인증 정보가 인증 서비스에 전달되지 않도록 입력 검증 추가`
